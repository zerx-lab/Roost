把下面这条内容写入本项目的记忆。只写仓库内的 `.omp/memory/`,不要使用 omp 用户级记忆工具或目录。

内容:$ARGUMENTS

步骤:
1. 内容为空时,从本次会话中提炼值得长期保留的信息:用户确认的决策、被否方案及原因、踩过的坑、外部平台事实。没有可记的就直接说明,不要写入。
2. 判断去处:
   - 长期有效且对大多数任务有用 → 写入 `.omp/memory/MEMORY.md` 对应小节(目标 / 决策 / 约束与陷阱 / 被否方案)的最前面;
   - 只与某个主题相关的细节 → 写入 `.omp/memory/topics/<slug>.md`,并在 MEMORY.md「主题索引」里补一行;
   - 一次性的过程记录 → 追加到 `.omp/memory/journal/<当前年-月>.md` 当天小节的最前面。
3. 格式:`- [YYYY-MM-DD] 结论 — 依据:<路径|命令|"用户确认">`。一条只写一个事实,不超过两行。
4. 写之前先读目标文件:已有同义条目就更新它;与新内容矛盾的旧条目要删除,或改写后移到「被否方案」。
5. 不写密钥、令牌、密码等凭据,也不写能从代码或 git 直接读出的内容。
6. 写完后运行 `scripts/check.sh`(至少看「项目记忆」一节),回报写入的位置和原文。
